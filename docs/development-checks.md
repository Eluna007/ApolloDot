# Development checks

Day to day, run `scripts/dev/check.sh` once. It checks staged, unstaged and
untracked-but-not-ignored files since HEAD; documentation changes never invoke Qt, CMake or
CTest. Already committed changes are outside the default scope and must be validated before
committing. Use `--full` to review the whole checkout.

| Scope | What runs |
| --- | --- |
| All changes | `git diff --check HEAD` |
| Changed QML | Qt 6 qmlformat comparison, qmllint (preparing a native build and the real Quickshell VFS when needed) |
| Changed first-party C++ | clang-format check |
| Changed shell scripts | bash syntax and ShellCheck; existing integration tests selected for configuration writing, Niri effects and Matugen paths |
| Changed Python | in-memory compile check, without writing `__pycache__` |
| core, CMake, QML tests | configure/build and the full existing CTest set |

Write QML formatting with `scripts/dev/format-qml.sh`, then run check only; do not repeat
format-check and lint separately afterwards. `--native` forces the build and CTest;
`--full` expands to repository-wide quality checks plus build and CTest, but does not
require a whole-tree format migration of legacy QML. For an explicit formatting audit use
`format-qml.sh --check-all`; to write across the tree use `--all`.

Validation scope and the conditions for widening a check are described in one place, in
[AGENTS.md](../AGENTS.md#workflow-and-validation). A visual tweak inside a shared component
does not automatically trigger a full check. With an existing build, run the affected tests
with
`ctest --test-dir build -R '<test-name>' --output-on-failure --no-tests=error`,
building first when a native build is required. QML unit tests are registered as
`qml_unit_tests`.

When Spotlight's settings declarations, the quick-action catalog or the generator change,
the entry point also generates and validates the search catalog. Run the catalog protocol
test on its own when no native build is needed; when one is needed, CTest runs it as part
of the set.

## QML tooling and generated artifacts

Prefer the Qt 6 tools in `/usr/lib/qt6/bin/`, overridable with `QMLFORMAT` / `QMLLINT`;
never pick up Qt 5 from PATH by mistake. `.qmlformat.ini` uses 4 spaces and Unix newlines,
with import/order normalization disabled. Use the whole-tree write `--all` only for an
explicit formatting migration; `--check-all` is not an everyday gate.

`.qmlls.ini` is a machine file generated by Quickshell and is ignored — never commit it.
Prepare the native build first, let `lint-qml.sh` generate or refresh the real tooling VFS,
then read `buildDir` / `importPaths` and pass them to qmllint as `-I` arguments. For
ordinary QML work the script prepares this on demand, without an extra rebuild.

## Dependencies (Arch Linux)

Install these manually based on what is missing. The commands below are for reference only;
the check scripts never run pacman or sudo.

```bash
sudo pacman -S --needed base-devel cmake ninja qt6-base qt6-declarative \
  qt6-shadertools qt6-tools qt6-wayland qtkeychain-qt6 libpipewire \
  clang shellcheck python git libxkbcommon systemd-libs wayland wayland-protocols
# The AUR package for libcava provides the required shared library and pkg-config
# interface; build and install it separately.
# The Matugen integration tests need:
sudo pacman -S --needed matugen jq
# The Niri configuration and display preview integration tests need niri validate
# (which does not start a compositor):
sudo pacman -S --needed niri
```

The window preview module requires `wayland-protocols >= 1.41`; the protocol code is
generated at build time by `wayland-scanner`. When a standard niri session does not provide
the single-window capture protocol, the Dock falls back to title mode automatically.

M3Shapes is a separately installed QML runtime dependency, packaged on Arch as
`qt6-m3shapes-git` (AUR). `lint-qml.sh` resolves it through Qt's system import root and
does not require `build/qml/M3Shapes`.

`base-devel` provides the compiler and build tools such as pkgconf; `clang` provides
clang-format.
Qt 6's qmlformat, qmllint and qmltestrunner belong to
[qt6-declarative](https://archlinux.org/packages/extra/x86_64/qt6-declarative/files/), and
LinguistTools belongs to [qt6-tools](https://archlinux.org/packages/extra/x86_64/qt6-tools/).
Quickshell's `qs` must also be available; use the distribution or `quickshell-git`
installation already on the machine, and do not replace a Quickshell that is in use just to
run checks. Cava must provide the `libcava` or `cava` pkg-config development interface; the
executable alone is not enough.

Query the packages above with `pacman -Q`. To check specific tools:

```bash
/usr/lib/qt6/bin/qmlformat --version
/usr/lib/qt6/bin/qmllint --version
pkg-config --modversion libpipewire-0.3
pkg-config --modversion libcava # or cava
```

## Confirmed causes of breakage and overhead (2026-09-06)

- This machine's `/usr/bin/qmlformat` is Qt 5 and reports `1.0`; the Qt 6 tool is installed
  at `/usr/lib/qt6/bin/qmlformat`, version 6.11.2. The old script relied on PATH directly
  and picked the wrong tool. The old `--no-sort` argument is also unsupported by this Qt 6
  version. Qt 6 is now selected explicitly, the ini settings are used, and the legacy
  argument is not passed. Neither uninstalling Qt 5 nor changing system links is required;
  `QMLFORMAT` / `QMLLINT` can override.
- The old convention was to run format-check and lint separately, then run a check that
  included both; the old check also unconditionally checked all shell and C++ files, built,
  and ran tests. This is now a single scope-selected run.
- The old format-check looked for tools even with no QML changes, and scanned the whole tree
  for tabs and CRLF. An empty scope now exits immediately, and the format comparison covers
  only the selected files.
- The old lint always scanned the whole tree. The baseline whole-tree lint for this round
  exited 0 but produced 5,206 warnings, including Quickshell dynamic typing, unqualified
  access and others, none of which have been attributed or fixed individually. The existing
  `--max-warnings -1` advisory policy is retained, and this result must not be read as "no
  problems". The new check reports only the count and keeps the full log; problems that make
  qmllint exit non-zero, such as syntax errors, still block.
- The native configure and build succeeded this round, and all 11 existing CTest tests
  passed; the main build and formatting dependencies are installed. Product source was not
  modified, nothing was bulk-formatted, no software was installed, and no shell was
  restarted.

## Handling failures

`check.sh` writes its output to a temporary `apollo-check.*` directory, and on failure
shows only the last 60 lines plus the log path. Logs are cleaned up on ordinary success and
kept when there are QML warnings. Read the failing stage first rather than re-running the
whole entry point repeatedly.
The CTest summary retains skip information; a skip is not a pass. When the Matugen
integration tests are selected on their own and matugen or jq is missing, the missing
dependency is reported directly; CTest's existing skip policy is unchanged.

QML tooling depends on the `.qmlls.ini` Quickshell generates and on its VFS; never fake a
qmldir or import path to "fix" lint. If an offscreen start does not produce a valid VFS, the
script reports the log and the commands to recover in a graphical session. Run the script's
suggested commands manually from a terminal in a graphical session (with `build/qml` on the
import path), then retry the failing stage. After a Qt or Quickshell upgrade, a rebuild and
a tooling refresh may be required.
Installing yet another formatting package does not solve this class of problem.

Diagnose a given environment blocker once, then report what is incomplete and how to
recover. Do not re-run passing stages for the sake of a final summary.

### Formatting tool blockers

Ordinary formatting differences should be fixed and work continued; only confirmed tool
problems — version incompatibility, formatting that does not converge — count as blockers.
`check.sh` currently exits on failure, does not continue to other stages automatically, and
has no option to skip formatting.
When that happens, keep the failure log and, for the current scope, separately run
`scripts/dev/lint-qml.sh`, which does not depend on formatting, plus any genuinely needed
syntax, build or existing tests. Do not re-run stages that already passed, and do not modify
the script to hide the failure.
State separately at the end what passed, what is blocked and what was not run, and give the
manual recovery commands from the relevant log.

After a local native module adds exports, qmllint uses `--bare` with explicit import roots
so Qt's default preference for installed modules over `build/qml` does not leave new types
unrecognized. The real Quickshell VFS is still used; do not edit the system import root or
the generated qmldir.
