# Single-window capture technical verification

This is a standalone Qt/QML verification entry point. It uses the `Apollo.WindowPreview`
native module to enumerate ext toplevels over a dedicated Wayland connection and capture
windows by their stable `identifier`. It does not start Apollo services, does not change
Dock settings, and requires no replacement of the system Quickshell.

The Dock uses `WindowPreviewManager` from the same module: it associates niri's decimal IPC
window ID with the ext identifier, creates sessions only for cards visible in the hover
popup, and shares window capture between consumers across outputs.
Capture is released when the popup closes, the window closes, the screen locks or the
connection drops. The Settings Center shows the thumbnail switch and size options according
to the current protocol capabilities. Title mode remains available, showing the icon and
title when single-window capture fails.

## Build

Run from the Apollo repository root (this depends on the machine's `wayland-client`,
`wayland-scanner` and `wayland-protocols >= 1.41`; the protocol code is generated by CMake):

```bash
cmake -S . -B build -G Ninja -DAPOLLO_BUILD_WINDOW_PREVIEW_PROBE=ON
cmake --build build --target apollo-window-preview ApolloWindowPreviewplugin
```

Building and unit tests do not depend on the niri source repository. Only the runtime
verification below needs a compositor that supports the relevant protocols.

## Connecting to a nested niri

Confirm `WAYLAND_DISPLAY` from the nested niri's log. The `wayland-2` below is only an
example and should be re-confirmed each time the compositor restarts. `--display` must be
given explicitly; it never connects to your everyday session automatically.

```bash
# Check the window identifier with a separate tool first; it is not the title,
# the app-id or a list index.
WAYLAND_DISPLAY=wayland-2 wayshot --list-toplevels-json

# Live view: select a window and press Start. Changing the selection during capture
# replaces the session; Stop clears the image and releases the buffer.
WAYLAND_DISPLAY=wayland-2 QT_QPA_PLATFORM=wayland \
  build/tools/apollo-window-preview --display wayland-2 --timeout 300000

# Protocol enumeration only, creating no display window.
QT_QPA_PLATFORM=offscreen build/tools/apollo-window-preview --display wayland-2 --list

# Substitute the real identifiers for 2 and 3.
QT_QPA_PLATFORM=offscreen build/tools/apollo-window-preview \
  --display wayland-2 --capture 2 --frames 10 --timeout 15000

# Repeatedly stop, create and switch targets, reporting per-frame and final
# resource statistics.
QT_QPA_PLATFORM=offscreen build/tools/apollo-window-preview \
  --display wayland-2 --capture 2 --alternate 3 --frames 2 --cycles 100 --timeout 30000
```

`--view IDENTIFIER` makes the GUI start previewing automatically. `--save /tmp/frame.png`
saves only the last frame when a batch run ends; the live image always goes straight from
SHM into a QImage and is then displayed by QQuickPaintedItem, with no screenshot loop
process and no PNG relay.

`--fixture A` / `--fixture B` create red and blue animated test windows with the same
app-id, showing a counter and a moving square; `--static` stops the animation. Start them
through the same `WAYLAND_DISPLAY`, then re-enumerate the identifiers. These windows have a
definite exit deadline, read no user files and start no terminal commands.

Batch exit codes: `0` for completion, `2` for a connection, protocol or capture failure,
and `3` for a timeout waiting for a new frame. The default runtime limit is 15 seconds,
adjustable with `--timeout`. A static image may produce only one frame, so a timeout does
not mean capture failed — check `frames`, `distinctFrames` and the failure reason together.

## Verification boundaries

- Required interfaces: `wl_shm`, `ext_foreign_toplevel_list_v1`,
  `ext_foreign_toplevel_image_capture_source_manager_v1`, `ext_image_copy_capture_manager_v1`.
- SHM supports ARGB8888 / XRGB8888. A single buffer is reused, at up to roughly 30
  requests per second, and the compositor may make later requests wait for content to
  change. The image size is the source window's pixel size, not the preview control's size.
- On resize, the buffer is reallocated once new constraints arrive; switching, stopping, a
  window closing or a disconnect clears the image and releases the session.
  Diagnostic statistics retain first-frame latency, frame count, size, SHA-256, exit reason
  and the process FD count.
- Non-normal buffer transforms and unsupported formats are currently rejected explicitly,
  rather than displaying an incorrectly oriented image.
- The Dock is limited to roughly 15 requests per second and caps the retained image's long
  edge at 512 pixels; the raw SHM buffer is still allocated at the window's size. The SHM
  CPU copy and QQuickPaintedItem drawing are not DMA-BUF zero-copy. The compositor and the
  application determine the actual update rate, and a hidden workspace may reduce it.
- Popups are not treated as separate tasks, and window identity is never guessed from the
  title or app-id. This standalone entry point does not run the Dock's grouping and hover
  UI. Minimization is outside the capture module's responsibility.
